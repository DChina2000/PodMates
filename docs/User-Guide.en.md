# Group Chat Bot Panel · User Guide

One program manages everything: QQ, WeChat secondary accounts, Discord, Telegram, LINE, YouTube, X and more, with any number of bot roles and long-term memory.
On the computer it is a single window; on a phone, open the same panel in a browser. 中文版：[使用说明.md](使用说明.md)

---

## 1. Installation

1. Double-click `PodMates-Setup-1.4.3.exe`.
2. If a blue **“Windows protected your PC”** dialog appears: click **“More info”**, then click **“Run anyway”**.
   (The program does not have a code-signing certificate, so Windows does not recognize it. This is normal.)
3. Click **“Next”** through the steps. The installer asks for the **install location** (by default it installs for you only and needs no administrator rights; you can also choose “Install for all users”, which does). By default, a desktop icon named “Group Chat Bot Panel” is created.
4. The panel opens automatically when installation finishes.

> Your data (Settings, Roles, Personas, People table, Memory, Backups) is stored in the **`data` folder inside the install folder** (program and data together; to move everything, move the whole folder). With “Install for all users” it is stored in `%APPDATA%\PodMates` instead. **It is not lost when you uninstall or reinstall** (the uninstaller asks whether to delete data; the default is to keep it). The program finds its data by itself at startup; autostart, backups, export/import and the diagnostics package all follow that location.
> When a new version is available, a notice appears at the top of the panel (it checks GitHub Releases once a day). The program **does not update itself**. Download the new installer and install it over the existing one; all your settings are kept.

## 2. First Launch: Setup Wizard

The wizard has eight steps. You can skip any step, and everything can be changed later in the panel:

1. **Password**: Set a password for the panel. You don't need to enter it when using the panel window on this computer, but you do when opening the panel on a phone or another computer.
2. **Provider**: Bots call a large language model to talk. Choose a provider (the default is DeepSeek, using the official `deepseek-flash`), paste your API key, and click “Test connection” (this does not use any quota).
   Don't want to store the key in the program? You can use an environment variable instead; see Section 4.
3. **Roles (角色)**: Pick a role template as your first role (recommended: “Gentle Group Member”, “Translator”, “Chat Summariser and Q&A”). You can also skip this step.
4. **User card**: how she should address you. “User” is a fixed card in the system (every install has it: admin, attitude “Close and caring”, everything else empty); this step fills it in: your name, your identity (her mom / dad …), what she calls you (several allowed; with “her mom” / “her dad” the common forms are offered to click: Mom, Mommy, Old mom, … / Dad, Daddy, …), and optionally your accounts on each platform. The identity and forms of address you enter here become the card's “All roles” relationship scheme (“daughter” is only the template's default wording, not a fixed relationship): personas write `{{用户}}`, which is replaced with this card's name (the same rule as `{{平台}}`; the model only sees the replaced result). Several forms of address are written into the persona as “称呼: A, B, C — switch between them as the occasion suits”. You can skip it; while the name is empty, sentences that contain `{{用户}}` and the paragraph generated from this card do not appear. Everything specific to a user lives only in this card; the program has no special handling for any particular person. Wherever people are listed, this card is shown as “User · name” with a “User” badge, at the top; it cannot be deleted, everything in it can be edited, and only one card in the whole table can be the user card.
5. **Memory**: She recalls past events that are “related in meaning” to the current topic, using a small model that runs on your computer. The wizard makes a recommendation based on your RAM: with 16 GB or more, it recommends the GTE model, which performs best (about 340 MB download, done in one click); otherwise it uses the small model bundled with the installer (no download needed).
6. **Platforms**: QQ / WeChat / Discord. Enable the ones you want (more platforms are on the **Accounts (账号)** page).
7. **Accounts**: Add bot accounts for each platform (Section 11 has step-by-step instructions).
8. **Finish**: Optionally turn on “Start at login” and “Run in background without a console window”.

You can run the wizard again later under **Settings (设置) → About → Run Setup Wizard again**. To try things out first without connecting any accounts, use the **Demo (体验)** page (Section 12).

## 3. Daily Use

- **Tray icon** (bottom-right of the taskbar, blue chat bubble): double-click to open the panel; right-click to “Start/Stop bot” or “Quit”.
- **Only one program runs per data folder**: on start-up the program first takes a system mutex tied to the data folder; if it cannot, one is already running (even if two start in the very same second, for example the installer opening one after installing and your deployment script starting another). The latecomer brings the open panel to the front (not for `--background` starts, which is what autostart and scheduled tasks use), waits a few seconds if the first one is still starting and has no panel yet, and then exits without starting the bot or touching NapCat or WeChat. If the first one crashes or is force-killed, the system releases the mutex by itself and the next start works normally. Two different data folders do not affect each other.
- **Closing the panel window does not stop the bot.** To fully shut it down, right-click the tray icon and choose “Quit” (this also shuts down the accounts' NapCat and QQ).
- **NapCat / QQ run independently, so a restart or an upgrade does not log QQ out**: the NapCat that the program launches is not tied to the program's process; its output goes to `napcat-logs\<QQ number>.log` in the data folder (cleared once fully read and over about 24 MB; the previous run is kept as `.log.1`). When the program crashes, is force-killed, is relaunched, or when you install a new version, NapCat and QQ keep running. On the next start the program first checks whether this account's old NapCat is still alive, reachable, and logged in as this account: if all three hold it simply re-attaches (the Logs page, NapCat category, says “re-attached to the NapCat that was already running; QQ was not logged in again”), and QR codes, kicked-offline and risk-control messages are still recognised, now from the log file; if any check fails it cleans up and starts a new one as before, and the log says why (no NapCat running / cannot connect / logged in as another account / started in another folder or on another port). It is only stopped when you explicitly close it: Stop on the account or Stop bot in the panel, Quit in the tray, or uninstalling. When an account is disabled, deleted or switched to “don't manage NapCat”, the NapCat it left behind is cleaned up on the next start. The first upgrade from an older version may still need one QR scan, because the older NapCat was launched through a pipe; later upgrades will not.
- Panel pages:

| Page | What it does |
|---|---|
| Overview (总览) | Running status, online status of each account, today's usage, recent activity |
| Messages (消息) | Group chats **and private chats** (filter All / Groups / Private; chats that are configured but have no messages yet are listed as “No messages yet”); speak manually as a role; click “Make her reply” on a message; recall her last message. “Would have said” messages from shadow mode are also here |
| Accounts | Add, start, and stop accounts for each platform; log in by scanning a QR code; edit nickname, avatar, signature, and group card |
| Roles | Each bot character: persona, one-line summary for the Gatekeeper, chime-in level, which relationship scheme each person uses for this role (identity / forms of address / attitude, edited on the person card), behavior settings, QQ group card. Can be created from a template |
| Schedule (排班) | Which role an account plays in each chat, time slot, and date (Section 6) |
| Personas (人设) | Module assembly (drag to reorder, toggle, edit), full view (the complete text actually sent to the model, copyable), version history, trial chat, archetype library |
| People (人物) | Person cards (platform accounts, relationship schemes — identity / forms of address / attitude, what she knows, admin status), groups, four levels of attitude |
| Chats (群) | Chat profiles (a one-line description of what the chat is), per-chat on/off and chime-in level, memory on/off, scheduled messages |
| Memory (记忆) | Notes about people, chat recaps, group memes, file excerpts; view source messages, edit, delete, review; semantic recall (on/off, embedding model); memory spaces; import past chat logs |
| Demo | Simulated chat group that connects no accounts (Section 12) |
| Logs (日志) | Live logs. The Gatekeeper gives a reason every time, whether it chimes in or not; filter by category |
| Usage (用量) | Statistics by day, role, chat, purpose, model, and platform; cache hit rate, average tokens per reply, trend chart; CSV export (Section 10) |
| Settings | Models & API, global defaults, platforms, access & security (password, phone, Tailscale), system (including diagnostics package and new version check), data & migration, about |
| Commands (指令) | Custom commands: when someone in a chat says this, do that (trigger, action, who may use it, where it applies, cooldown); see Section 17 |

**Settings are layered**: Global defaults → Platform → Role → Role on a platform → Chat → Role in a chat. Anything you haven't changed inherits from the level above.
Each item shows “Inherited: ××” or an orange “Changed” label. Changed items can be reset with “Restore inheritance”. Common settings are shown up front; less common ones are under “Advanced settings”. Every item has a default value, so the bot runs normally even if you change nothing.

**Management commands** (@-mention her in a chat, followed by one of these fixed phrases):

| Phrase | Effect |
|---|---|
| “闭嘴” (be quiet) / “闭嘴30分钟” (be quiet for 30 minutes) | Stay silent in this chat (default: 30 minutes) |
| “恢复” (resume) | Cancel silence |
| “换温和版群友” (switch to Gentle Group Member) / “换人设 温和版群友” (switch persona to Gentle Group Member) / “换人设 2小时” (switch persona for 2 hours) | Temporarily switch to a role (or to a persona). Can include a duration, such as “2小时” (2 hours) or “30分钟” (30 minutes). Without a duration, it lasts until the end of the day. When it expires, she returns to the schedule. If the name matches no role or persona, she replies as ordinary chat |
| “换回” (switch back) | Cancel the temporary switch and return to the schedule right away |
| “插话开” (chime in on) / “插话关” (chime in off) | Turn this chat's proactive chime-in on or off. It is stored for **the account that received the command, in this chat**: it applies no matter which role is on duty (it survives shift changes), other accounts in the same chat are not affected, it survives restarts, and it takes priority over every panel setting. The panel's Chats page shows it at the top, and “Clear” returns to the panel settings |
| “插话力度 1~5” (chime-in level 1–5) | 1 = very rarely … 5 = chatterbox (same scope as above) |
| “状态” (status) | Report silence, chime-in, persona, and today's usage |
| “撤回” (recall) | Recall her last message (not supported on WeChat) |
| “忘掉 某人/某事” (forget someone/something) | Delete related memories. At least 2 characters are needed (if it is too short she asks what to forget); a backup is made first, and an admin can undo it on the Memory page |
| “忘掉我” (forget me) | Any group member can have her delete memories about themselves. Admin People cards are the exception and can only be edited in the panel |

**Management commands run the moment they arrive**: they are not put in the reply queue and are not subject to the “minimum gap between two replies” — even with other @-mentions queued or while waiting for the gap, a command takes effect immediately and its confirmation is sent at once, signed with the role **after** the change. The other queued @-mentions are then answered by the new role; when @-mentions are merged, the command message does not count as being called; after “be quiet”, any reply that role has not sent yet (queued or still being written) is discarded. Custom commands also run on arrival. Command replies do not use up the gap timer.

Who can use which command is set under **Settings → Global defaults → Permissions**. By default, only “Me” (meaning people ticked “Admin” in the People table) can use them. Anyone without permission who sends a command gets her own way of declining.

**Command list**: say “指令” or “帮助” to her (@her in a group, or in a private chat) and she replies with the list of commands **you** can use (the first line is “你能用的指令：”, then one line per command: the phrase and what it does). In a group only the commands you have permission for under “Command permissions” are listed; the user card's owner chatting privately gets the private commands; someone with no usable command gets “你在这里没有可用的指令” (“you have no commands here”). The same table (all commands, where to say them, who can use them) sits next to “Command permissions” under Settings → Global defaults → Permissions.

**Chime-in limits** (Settings → Global defaults → Chime-in; they stack and the strictest one wins): “Hourly chime-in limit (whole account)” defaults to 360 and is the total across all chats for the whole bot account, because platform risk control applies per account; “Hourly chime-in limit (per chat)” defaults to 90; “Daily chime-in limit (per chat)” defaults to 600; topic starters when a chat goes quiet are at most 12 per chat per day. Sending a sticker counts as one message.

## 4. Providers and Models

In the panel, go to **Settings → Models & API**.

- **Defaults**: The main model, Gatekeeper, memory consolidation, and vision all use DeepSeek's official `deepseek-flash` (an official alias that always points to the latest Flash, so you don't need to update version numbers). You can choose the provider and model separately for each of these four.
- Two tabs:
  - **Third-party providers**: Dozens are built in (data from [models.dev](https://models.dev), MIT license). Pick one from the dropdown, enter its key, and you're ready. Click “Update provider catalog online” to refresh the list.
  - **Custom API**: Your own relay service, a local Ollama or LM Studio, a company intranet gateway, etc. Just enter the endpoint URL and protocol. Three protocols are supported: OpenAI-compatible, Anthropic, and Gemini.
- Configured providers are shown as cards with the name, key status, and a connection status dot (green = last test passed; red = not connected; grey = never tested). You can test, edit, or delete them.
- **How keys are stored**: Keys are kept in local data, **encrypted with your Windows account** (DPAPI). They are not included in the installer, logs, or diagnostics package, and are left out of exported data packages by default. You can also choose **not to store** the key: enter an “environment variable name” (for example `DEEPSEEK_API_KEY`) and leave the key field blank. The program then reads that environment variable, and the panel shows the key as “from environment variable XXX”.
- **Choosing a model**: The “Select…” button next to the model field fetches the current model list from the provider (if that fails, the list from the built-in catalog is used). Models are tagged “Vision” and “Reasoning”. You can also type a model name directly. When the model is not in the selected provider's list, the panel shows a note under that field (it does not block saving or change any setting).
- **Thinking intensity**: Providers write this differently (Zhipu and DeepSeek use `thinking` + `reasoning_effort`; OpenAI-style providers only recognize `reasoning_effort`; Anthropic uses `thinking` + `output_config.effort`; Gemini uses `thinkingConfig`). The program adapts automatically. For providers it does not recognize, no thinking parameters are sent. If needed, change “Thinking intensity format” on the provider card or enter “Extra request parameters”. **The options in the panel list the levels the model really supports** (only restricted when the provider catalog has data for that model, otherwise the full list as before): e.g. the GLM-5.3 family has forced thinking that cannot be turned off, so only Low / High / Max are offered (the note says leaving it unset equals Max), and the request only ever carries the officially supported `low` / `high` / `max` — never `medium`, and no longer “nothing at all”. Saved values are converted only where the model does not support them: Medium becomes the nearest level, High; “no thinking/default” on a model that cannot turn thinking off stays unsent and shows as “Max (default)”; values set by hand such as High or Low are untouched (the stored value itself is not rewritten, the conversion happens when the request is sent and when the panel displays it). **The thinking intensity of the gatekeeper, vision, memory extraction and main reply all default to High**; when the model does not support High, the closest supported level is used.
- **Vision**: Settings → Models & API → turn on “Vision”, then choose a vision-capable model for “Vision model” (DeepSeek's official documentation says `deepseek-flash` supports image input). Each image adds one extra model call. **WeChat can see pictures too**: when a picture arrives, the program downloads it (first with wxauto4's `ImageMessage.download()`, and if that fails by right-clicking “Copy” and reading the clipboard; WeChat 4.1.15 shows pictures in the chat as just the two characters “图片”, which are recognised as pictures too. The download itself has no timeout parameter: the separate-window mode queues it on the WeChat thread; the main-window polling mode runs it on a dedicated download thread and waits at most 25 s for both ways together, so receiving is not stuck), hands it to the same vision flow and writes it in the context as “[Picture: …]”, exactly like QQ; the switch, the vision model and the usage cap are shared with QQ (at most 2 pictures are described per message; when vision is off only the first 3 placeholders are written). **Stickers that members send in WeChat are seen too** (including animated pictures sent from the album, which WeChat turns into stickers): sticker-type messages (type emotion, or content such as “动画表情”) are not downloaded at all: in WeChat a sticker cannot be opened full-size or saved as a file the way a picture can, so the program **screenshots the part of the chat where that sticker sits** and hands it to the same vision flow, then writes it in the context as “[表情: …]” so she knows it is a sticker, not a photo (the screenshot is cropped down to the sticker itself, dropping the avatar, and the nickname row of a group chat when blank space separates it from the sticker; for an animated sticker three frames are captured one after another and shown to the vision model together, and when the three frames are the same only one is handed over); before grabbing, it makes sure that area is showing the window this message lives in (no such window means no look), is big enough and lies inside a monitor — WeChat’s own menus and other chat windows on top all count as covering it, and a failed grab is written as just “[表情]”, logged once and not retried; before grabbing it also closes WeChat’s own small menus covering that area (it only sends Esc or Close to that menu, never touches the main window) — if the menu cannot be closed, or another window covers the area, the sticker is not screenshotted; also, after reading messages WeChat leaves a small “@someone / nudge” menu next to the avatar of the newest message from someone else, so every time PodMates finishes reading messages it sends one Esc to that menu to close it (again only to the menu, never to the main window; if it cannot be closed it is left alone and logged); with “move the WeChat window off screen” on, the window is moved back first and out again afterwards, without stealing the foreground; screenshotted stickers are remembered for “the same picture is looked at only once” by image fingerprint (dhash, taken from the cropped first frame), so small background and position differences still count as the same sticker; QQ custom stickers and animated pictures (a NapCat image segment with `sub_type` 1 or a `summary` containing “表情”) are written as “[表情: …]” as well, while mall stickers (`mface`) are still written as just “[表情]” and left to sticker learning. The new switch **Also look at stickers sent by members** (Settings → Models, `vision_stickers`, on by default, same scopes as “Vision”, only meaningful while “Vision” is on): when off, WeChat stickers are not screenshotted and QQ sticker images are not looked at — both are written as “[表情]” — while ordinary photos are still looked at; each sticker adds one vision call, so turning it off saves usage. WeChat stickers are looked at but not learned (not handed to sticker learning). **The same picture is looked at only once**: the description is remembered by “picture content + vision model” (all platforms) and reused when the same picture shows up again, without calling the model (screenshotted WeChat stickers are keyed by the image fingerprint dhash instead — only an identical fingerprint counts as the same sticker, so small background and position differences still match); changing the vision model looks again; only successful descriptions are remembered; it is cleaned together with the chat history (see below) and has no switch of its own. A failed or timed-out download (25 s) is written as “[Picture]” as before (“[表情]” for stickers; so is a message recognised as a picture but not downloaded — a bare “图片” is never left in the text), logged once and not retried; with vision off or no vision model nothing is downloaded and no sticker is screenshotted. The downloaded file is read into memory and deleted at once. Pictures in private chats are seen as well.
- **Fallback provider**: If the main provider fails (insufficient balance, rate limiting), the program automatically switches to the fallback. Off by default.
- **New-model reminders and replacement** (reminds only, **never replaces anything by itself**): Settings → System → “How often to check for new models (hours, 0 = never)”, default 24. When it is time, the program asks each provider you have set up (any provider used by the main model, gatekeeper, memory extraction, vision or backup at any settings level) which models it offers now: it asks the provider first and, if that fails, refreshes the built-in catalog online once and uses the catalog's list; no search service is involved and no tokens are spent. **The first time it only records, without reminding**; only models that appear afterwards count as new. After a start it also counts from the last check, so it does not check right at startup.
  - **Same series**: two ids are the same series when they are equal once the version numbers are removed and the new version number is larger (e.g. `glm-5.3-flash` → `glm-5.5-flash`); date suffixes are ignored, “4-5” is read as 4.5, and ids with more than one version number (e.g. `qwen3-235b`) are not certain, so they do not count. When a model you use gets a newer version in the same series you are reminded once (one unread notice on the Overview plus a private message to the user card's owner) naming the old and new model, what they are used for, and the capability differences from the catalog (can it see images, can it use tools, how long it can read; items the catalog has no data for are left out). New models of another series are not reminded about; they are only listed under that provider's card as “New models from this provider” with the date found.
  - **Replacement**: “Replace in one click” on a provider card and the private commands share one procedure: first a real call to the new model to confirm it connects; if vision is among the places to replace, it also confirms the new model can really see images (it reads a small picture); if it does not pass, nothing is replaced and you are told why. If it passes, in **all scopes** (global, role, platform, chat and their combinations) the main model, gatekeeper, memory extraction and vision that use this provider and equal the old model are switched to the new one, and a backup model equal to the old one too; a log line is written. Thinking effort follows the existing rule that a saved level the new model does not support becomes the nearest one. If the basic call works and only vision fails, “Replace only what can be replaced” is offered (vision keeps the old model); when the new model can see images and vision is not using the old model, “Replace vision too” appears. “Not now” reminds you again after “Days before reminding again after ‘not now’” (default 7), “Never replace” stops the reminders; models set to not now / never are listed under the card, each with “Undo”. “Check for new models now” checks immediately.
  - **Private commands** (only the user card's owner; anyone else saying the same words just chats): **换** (replace according to the latest proposal), **换能换的**, **看图也换** (if vision was off it is not turned on for you, only a reminder is added), **不换** / **不换 30 天**, **一直不换** / **别再提**, **换模型 old new** (replace old with new on that provider; the new model must be in its model list), **查更新** (check for new models and a new version right now; a new version is still only a reminder). With no pending proposal, “换”, “不换” and “一直不换” are treated as ordinary chat.
- **Proxy**: Reaching overseas providers and platforms (OpenAI, Anthropic, Gemini, Telegram, LINE, YouTube, X, Discord, etc.) usually requires a proxy from mainland China. Enter the proxy address (for example `http://127.0.0.1:7890`) under “Models & API”, then tick “Use proxy” on each provider card or account.

## 5. Role Templates and Archetypes

In the panel's **Roles** page, the top half is “My roles” and the **bottom half always shows the “Role template library”** (28 templates; also available in the wizard). Templates are grouped into six categories; each card shows a name, a one-line description and a “Use this” button; “Expand preview” shows the full persona text; you can filter by category and search by name, and it works on a phone too. The “Create from template” button at the top scrolls straight to the library. Templates are grouped by category:

- **Original characters** (1 role): Dolphin Girl (fights back without limits, sharp-tongued, uses the “group member personality” module, comes with “Archetype 171”). Her shell is followed by the shared modules: group member personality, Lacanian streak, AI identity, Archetype 171, speaking style and boundaries. The seven philosophy modules (Nietzsche, Hegel, Althusser, Badiou, Heidegger, Schelling, Hölderlin) are still in the shared modules and can be attached to any persona.
- **Entertainment & companionship**: Gentle Group Member, Cheerleader, Deadpan Joker, Late-Night Chat Buddy.
- **Academic explainers**: Economics Professor, Business School Professor, Political Science Professor, Psychoanalytic Theorist, Philosophy Professor, Historian, Sociologist, Popular Psychology, Popular Law, Math & Programming Teacher, Literary Critic.
- **Lifestyle & health**: Nutritionist, Fitness Coach, Routine Advisor, Emotional Companion (not therapy).
- **Practical tools**: Translator, Writing Editor, Coding Assistant, Study Planner, Chat Summary & Q&A.
- **Game hosts**: Tabletop RPG Game Master, Puzzle Host, Werewolf Judge.

Selecting a template **copies** it into a new role, which you can then edit freely. The persona is copied only the first time you create a role from that template; creating another role from the same template reuses the existing persona instead of adding a same-named one. For an edited variant, use “Duplicate” on the Personas page (the copy gets a suffix 2, 3, … and editing it does not affect the original). Each template has its own core module. Medical, nutrition, legal, and psychology templates all state that they are “mainly for popular science and giving direction; they do not diagnose, and for serious matters consult a licensed professional.” Apart from Original characters, templates do not include an archetype by default. Dolphin Girl's shell says “You are the daughter of ‘{{用户}}’”, shown with the name of the card marked “User” in the People table. The full template text is in [模板文本.md](模板文本.md).

Want to add your own templates? Create a `templates` folder in the data directory and write `.md` files in the same format as those in `assets/templates`; if the same template id exists in both places, yours wins. Local templates are not bundled with the installer and are not overwritten by upgrades.

You can also do this from the panel without touching files by hand (it works on a phone too). **“Copy to local templates”** on a template card writes that template as-is to `local-<template id>.md` in the `templates` folder of the data directory (for a template whose shell lives in a bundled file, the shell text is written into the body) and shows the full path. A local template's card carries a “Local” badge and an **“Edit”** button that opens the whole file as text; before saving, the format is checked (at least `id`, `name` and `category` are required, and the `id` cannot change) and nothing is saved if something is wrong. A template copied with “Copy to local templates” whose bundled counterpart still exists also gets **“Restore the bundled one”**, which, after you confirm, deletes that `local-<id>.md`. Local files you put there yourself can only be edited, not deleted. Personas already created do not change along with the template: to make a role use the new text, edit the persona on the Personas page, or delete that persona and create the role from the template again.

**Admit being an AI (master switch)**: there is a switch at the very top of the Overview page. On: when asked whether she is an AI she admits it (the “AI identity” module in a persona, and sentences such as “You are an AI; admit it when asked” in the templates, appear as usual). Off: none of that appears and the prompt no longer says she is an AI. Each role also has a three-way option on the Roles page: follow the master switch (default) / on / off; a role set to on or off is not affected by the master switch. A platform or a single group can override it as well (layered like any other setting: role in group → group → role on platform → role → platform → global). New installs default to on. When writing your own persona: a module can be marked “Governed by the ‘Admit being an AI’ switch”, and text written as `[[AI|this text]]` follows the switch too.

In the chat history shown to the gatekeeper, her own messages are labelled “她（自己）” (“her (self)”).

**Archetype library**: The installer only includes “Archetype 171”, which Dolphin Girl uses. To use other archetypes, go to **Personas → Archetype library → Import archetype file** and select archetype JSON files (you can select several at once). On import, only the `id`, `coreProposition`, `realityExpansion`, and `characterTendency` fields are kept. Everything else in the file is discarded and never enters the program.

Terms in personas such as “QQ group”, “QQ plain-text typing”, and “QQ nickname” are **shown according to the current platform** (QQ group / WeChat group / Discord server, etc.). The format requirement “No Markdown, lists, headings, or bold” is applied only on platforms that do not render Markdown.

### Role tags and the “relationship schemes” on person cards

The same person can deserve a different relationship with different roles: Dolphin Girl calls him mom, while a “business-school professor” who has taken over the shift should call him a classmate or student. So the **identity, forms of address and attitude** on a person card are no longer one fixed set; a card can hold several **“relationship schemes”**.

- **Each scheme** has a name (e.g. “daughter”, “teacher and student”), a relationship (who she takes this person to be: it goes into the prompt's small heading and the “is …” sentence), forms of address (several allowed) and an attitude, plus a **scope**: “All roles” / “By tag” (one or more tags) / “Specific roles” (one or more).
- **Role tags**: add tags to a role on the Roles page. Roles created from a template get the template's category as a tag by default (“Original characters”, “Academic explainers”, “Practical tools”, …); on upgrade, existing roles whose source template can be recognised get it too.
- **Which scheme a role uses for a person**: specific roles > by tag > all roles; if several match at the same priority, the one listed earlier on the card is used (the card has ↑ ↓ to reorder) and a conflict warning is shown. If none match, the card's own set is used (it follows the first “All roles” scheme).
- Admin rights and recognising a person by the “〔name本人〕” marker in the chat history are independent of schemes and unchanged.
- The Roles page shows, for every person, which scheme this role currently uses and by which rule. The old per-role “override the attitude toward a person” is gone — to set something different for one role, add a “Specific roles” scheme on that person's card, so the attitude is decided in one place only.
- **Upgrading from an older version**: the identity, forms of address and attitude already on a person card become a scheme called “默认” (all roles) unchanged; a role's old attitude override toward someone becomes a “Specific roles” scheme on that person's card (identity and forms of address copied from the default one), and the override on the role is cleared. So before and after upgrading, every role sees exactly the same person card text.

## 6. Schedule: The Same Account Plays Different Roles in Different Chats and Time Slots

In the panel, open “Schedule”.

- **Rule** = a set of conditions + one result. All conditions are optional (leaving one blank means no restriction): platform, account, chats (multiple selection allowed) or chat group, date range, weekdays, and daily time window (may span midnight, e.g. 22:00 to 02:00; the part after midnight counts as the previous day's weekday and date).
- **Result**: either a fixed role, or rotation among several roles (in order or at random; switching by day or every few minutes). Random selection also stays fixed for a period of time and does not change on every message.
- **Priority**: Rules are checked from top to bottom, and the first match wins. Drag to reorder. You can also click “Auto-sort by specificity” (specific date > weekday + time window > weekday only > daily time window > no restriction). If nothing matches, the account's “Default role” (set on the Accounts page) is used.
- **Chat groups**: Create groups at the top of the “Chats” page, add chats in each chat's settings, and then select a whole group directly in rules.
- **Checking the results**: “Who's on now” shows which role is active in each chat and when the next switch happens. “Schedule view” shows a weekly or monthly view. Rules that can never take effect, expired rules, and time slots with no role are flagged at the top of the page.
- **Shift changes**: You can have the new role send a greeting in the chat (off by default). The QQ group card can change automatically with the role (off by default). The avatar and nickname are shared by the whole account and do not change by chat or time slot.

**Memory is isolated per group and per private chat by default**: what is learned in each group or private chat (notes about people, chat recaps, group memes, things told to “remember”, file excerpts, the chat's style profile, stickers) is used only in that group or private chat and never leaks into another; semantic recall also searches only within the current chat's scope. A private chat is kept per “which account × which person”; notes about people are also kept separately for each role (after a role change, recaps and memes still carry over).
- To let several groups (or private chats) share memory, create a space under “Memory → Memory spaces” and bind them together (you can also bind by role or platform); a custom space takes priority over the default isolation. File excerpts choose their space by the “file excerpts” kind; when several chats' style profiles are bound to the same space they share one copy. The People table (person cards, forms of address, attitudes) is not memory and applies to all groups.
- When upgrading from an older version, the notes about people that used to be shared per role are split back to the groups they came from, using each record's source. Notes saved in private chats are claimed only when the account × person can be determined; anything whose source cannot be told is kept (nothing is deleted) in an “Unassigned” space on the Memory page for you to decide.

### How memory is consolidated and put into the prompt

- **Group events are merged in layers and never rewritten once written**: every 50 messages (“Messages per memory consolidation”) are consolidated into one unit, layer 1 — no length limit, only things that will matter later (chit-chat and greetings are left out; long if there is a lot, short if little). Every 5 units are merged into the next layer, whose length limit is “the **actual length** of the merged parts × ratio” (ratio: Settings → Global defaults → Memory, default 0.7; choose 0.5 / 0.6 / 0.7 / 0.75 / 0.8 or type your own; if that works out to less than 30 characters the limit is 30, so a merge does not become too short to understand). When merging: each event says who did what to whom; if something changed later, write the state after the change and one line on how it changed; names as in the original, no feelings, nothing that is not in the original. A written unit is never rewritten; changing the ratio only affects later merges. Every unit records its layer, the range of messages and the time range it covers, and the people who spoke or were mentioned in it.
- **Nothing is lost**: the recent raw messages given to the model are at least the last “group context messages” and always reach back to where the latest recap ends — every message in a chat is either in a recap or in the raw messages. A segment that fails to consolidate is retried after a while; after 3 failures in a row its original lines are stored as a layer-1 unit, so nothing is lost.
- **Layout**: the coarsest written layer first covers all older history; if there is room, from the newest backwards each unit is replaced by the next layer covering the same range (newer = finer) until it no longer fits; if there is not enough room, the earliest units give way first. Units are in time order, each labelled with its time range (e.g. “Oct 20 – Oct 24”), under the heading “What happened in this chat before (in time order, earlier = coarser)”.
- **People: impression + raw notes**: notes are kept forever by default (when “Memory retention days” is set, the section below applies), with date and source (said by themselves / said by others / her inference). Each person also has one “impression” per memory space describing how they are now; when their notes are pushed out of the latest 100 (Settings “Latest notes per person”, default 100), the pushed-out ones are folded into the impression — nothing in the old impression is dropped unless later facts overturn it, overturned items note how they changed, self-stated and inferred facts are kept apart, no length limit. If the same person has the same notes in the spaces of several roles, the impression is updated only once. Things asked to be remembered (“remember…”) are not folded and are included verbatim every time. For each person present the prompt carries: impression, latest 100 notes, and what they asked her to remember.
- **Retrieval by person**: layer-1 recaps already merged into upper layers and not shown as such, plus the present people's older notes that are not shown, are scored by the program by id (people mentioned in this message +2, people who spoke in the recent raw messages +1, her own accounts excluded); higher scores first, ties by recency, shown in time order in a small section “Older things about the people here”; at most 75% of the memory section and at most 1000 items (both are advanced settings under Settings → Memory — “Share of the memory section that retrieved old records may use” and “Maximum number of retrieved old records at a time” — adjustable globally and per chat). When space is tight the order is: impressions and requested-to-remember items of people present (always kept) → the coarsest layer → the present people's latest notes (when they do not fit, the notes of people not mentioned this time give way first, earliest first within the same relevance score; what gives way becomes a retrieval candidate) → retrieval → what is left refines the recap, newest first. The coarsest layer is the only complete coverage of the chat's old events; most of the notes' content is also in the recap, and the impression already covers how each person is doing. Group memes and old things recalled by semantic recall also count towards this section's room (including “Maximum memory to include”); when they overflow, less is included following the order above; impressions and requested-to-remember items are still always kept.
- **How much room**: the memory section has no fixed limit: it is how long the model can read minus the reply length and everything else (persona, people table, raw messages…). “How long the model can read”: what you fill in under Settings → Models & endpoints → Edit provider wins; otherwise the smallest of the provider catalog's value, the limit stated in error messages and limits remembered from past rejections; 1M if none; the largest request that ever succeeded is the floor. When a request is rejected for being too long, the program remembers the limit from the error, lays the memory out again under the new limit and resends once — the reply is not lost. To save usage, enter “Maximum memory to include” (Settings → Global defaults → Memory; 0 = no limit); when exceeded, content gives way in the order described above under “When space is tight”.
- **Retention days**: “Memory retention days” (Settings → Global defaults → Memory; 0 = forever by default, adjustable per chat) governs old notes, recaps, group memes and file excerpts. “Also expire notes about people with the retention days” is on by default: notes about people also expire, and once they do, this person's impression in this memory space is rewritten from the notes that remain (the same as after deleting notes in the panel); if no note is left, the impression is cleared. Turn it off and only the rest is cleared — notes about people never expire. Items asked to be remembered, style profiles, stickers and impressions are never cleared by the retention days. Separately, “Chat history retention (days; 0 = permanent)” (Settings → System, default 30, 0 = never cleaned) governs the chat history and the remembered picture descriptions; it is a different setting from the memory retention days.
- **Memes** are looked up among all of the chat's memes by keyword, not only the newest.
- **Forgetting and reset**: “forget me” deletes the person's notes and impression, plus the recap units that contain them (and the upper layers covering those); “forget ××” and Reset memory work the same way: whoever the deleted notes belong to, that person's impression is rewritten from the notes that remain (whether or not the impression contains the same words). Deleted upper layers are later re-merged from the remaining lower units. All three make a backup first and can be undone on the Memory page. The **Memory page** can view, edit and delete recap units (with layer and time range) and impressions; after a unit is edited, the upper layers covering it are rewritten from the edited text.

## 7. Semantic Recall

Besides remembering the people present, the chat recap, and the group memes that came up, she also recalls past events that are “related in meaning” to the current topic. This works even when the person involved isn't mentioned and no keyword matches. The same memory is included only once; old notes recalled by semantic recall carry a date just like ordinary notes.

- The switch is under “Memory → Semantic recall” and is on by default. Each memory space can also be turned off on its own at the bottom of “Memory → Memory spaces”.
- **Uses a local small model by default** (BGE small Chinese, bundled with the installer; no API calls, no cost; uses about 50 MB of extra RAM). When the computer has 16 GB or more of RAM, the wizard recommends one-click download of the best-performing GTE multilingual base (about 340 MB; uses about 600 MB of extra RAM).
- You can also switch to an API: choose “API”, pick a preset (SiliconFlow (硅基流动) Qwen3-Embedding-4B is recommended, about 0.14 CNY per million tokens), and enter your API key.
- **Outdated vectors are rebuilt automatically**: after changing the model or source, or when some memories have never had vectors calculated (imported, restored, or a previous attempt failed), the program checks at startup and every half minute while running, and recalculates them in the background by itself; no clicking needed. The page shows the status and progress (the “One-click rebuild” button stays for starting immediately or recalculating everything). Rebuilding never blocks replies, and semantic recall uses only the part already calculated during a rebuild, never mixing old and new models. If the local model is not downloaded yet, the API is not set up, or the hard usage cap is in effect, it does not keep trying: the page states the reason, one warning is logged, and it catches up automatically once the condition is fixed. If a rebuild fails, it retries after a while, waiting longer each time.
- **Model download fails (network in mainland China)**: The program tries ModelScope (魔搭, directly accessible within mainland China), Hugging Face, and hf-mirror in turn. If none of these work, download manually:
  1. Open the ModelScope website and search for the model name (for example `onnx-community/gte-multilingual-base`). Go to “Model files” and download the matching file from the `onnx` folder (the list shows which file to use, such as `model_quantized.onnx`), along with `tokenizer.json` from the root folder.
  2. Rename the ONNX file to `model.onnx` and put it together with `tokenizer.json` in the folder shown on the page (`数据目录\models\<模型名>`).
  3. Return to the page and refresh. Once it shows “Downloaded”, you can select it.
- “Try it” lets you enter two sentences to see how similar they are. This helps you decide whether to adjust the “Similarity threshold” (Settings → Global defaults → Memory → Advanced). The default of 0 uses the threshold calibrated for each model.

## 8. Reading Files

**Off by default.** Turn on “Read files” under Settings → Global defaults → Files. You can also turn it on or off for an individual chat in that chat's settings.

- **When to read**: By default, “Only when mentioned”: she reads a file only when someone @-mentions her or replies to the file message. (If someone @-mentions her without replying to a file, she takes the most recent file that person sent within the last 15 minutes.) You can also choose “Read every file received”.
- **How the content is used**: The file is downloaded to a temporary location. After the text is extracted, the **original file is deleted immediately**. The text is split into fragments and stored in memory (as vector embeddings, so related content can be recalled later), and this reply includes an excerpt. You can optionally choose “Keep original files for N days” and set a total storage cap; when the cap is reached, the oldest files are deleted automatically.
- **Limits**: Maximum size per file (default 10 MB), maximum tokens per read (default 6000), and allowed formats (PDF, Word, Excel, PowerPoint, text and code, images; the first five are enabled by default). **Parse only, never execute**: macros are not run and links are not opened. Compressed files have a limit on their size after extraction.
- Currently, file messages can be read on QQ, Discord, Telegram, and LINE. WeChat and comment-section platforms do not support files. Scanned PDFs (with no text layer) cannot be read.

## 9. Reply Language

Settings → Global defaults → “Reply language”: the default is Chinese. Role, platform, and chat can each be set separately. Options include English, Français, Deutsch, Italiano, Русский, 日本語, Español, 한국어, العربية, فارسی, Português, and more. There is also “Follow the other party's language.”

## 10. Usage

Besides statistics by day, role, chat, purpose, model, and platform, the Usage page also includes **cache hit rate**, **average tokens per reply**, **thinking tokens** (shown only if the API returns them), **cache writes** (shown only if the API returns them), and a **trend chart**. You can **export it as CSV**. It only tracks tokens and call counts, and does **not convert them into money** (prices and discounts vary by provider, so refer to your provider's bill).

### WeChat Secondary Account

1. **WeChat version**: The program uses wxauto4 for UI automation. wxauto4 does not state an exact version range; its PyPI description has just one line, “suitable for the latest 4.1.8”, so the program treats **4.0 – 4.1.8** as its declared range (we set that range from that line). Every time it connects to WeChat the program checks the local version, and the panel's “Accounts → WeChat” page shows it: green = inside the range, usable; blue “verified” = outside the range but confirmed working on a real machine by us (currently **4.1.15**, receiving messages through “main-window polling”); the wording never says “unsupported” for it; yellow = outside the range and not verified (or too old), likely to fail to connect or break when the UI changes. In the last two cases the program **notifies you** (once per version): an “unread notification” on the Overview page; a message to the accounts on your “user” card (sent from one other online account that can reach you, never the account that has the problem: QQ by QQ number, WeChat by secret remark, Discord and Telegram by ID); and a Windows tray balloon. **Notifications only ever go to you in private: the accounts on your person card for that platform are tried one after another, and on WeChat the message is sent only after switching and confirming that the chat now open is exactly your private chat — if it does not match, the next account is tried; if none can be reached, the notice stays only in the panel's “unread notifications” and is never sent into any group** (the “how it was sent” field on that panel notice names the platform only once a message really went out). We recommend turning off automatic updates in WeChat's settings so that it does not upgrade itself to an unverified version.
   **wxauto4 update reminder**: once a day the program checks PyPI for a new wxauto4 (can be turned off under “Platform settings → WeChat”; on by default). If there is one, the Overview and “Accounts → WeChat” show a notice and you get one private message with the new version number and the WeChat version it declares support for; if the new version covers a newer WeChat, it says “you can upgrade WeChat to X”. It only reminds you and **never upgrades by itself**: to upgrade, stop the WeChat account on the Accounts page first, then click “Upgrade wxauto4” under “Accounts → WeChat” (installed into `data\pylib`); a failed upgrade rolls back to the original version automatically and is logged; after a successful one, restart the program for it to take effect.
2. On this computer, **open WeChat and log in to the secondary account**.
3. Panel → Accounts → turn on the WeChat switch → click **“Download component”** (wxauto4, about 2MB, downloaded once from the official PyPI; it does not declare a license, so it is not distributed with the installer).
4. Click **“Add”** → under “Chats to monitor,” enter the **chat name** where she should speak (exactly as it appears in WeChat). For a private chat, enter the friend's remark name and choose “Private chat” as the type → save → start.
5. **Recognizing people by a secret remark**: In the secondary account's WeChat, give your main account (and anyone else she should recognize) a remark name that only you know. Then go to the panel's **People → the matching person card → WeChat secret remark** and enter the same remark. Until this is set, she cannot recognize that person in WeChat.
6. **Note**: The WeChat window must stay open (other windows may cover it, but do not minimize or close it). Only **one** WeChat secondary account can run on one computer. In WeChat, messages cannot be recalled, and the program cannot change nicknames or avatars.
7. **Identity binding (so your main account is never used as the bot)**: the WeChat logged in on this computer may be your own everyday account, so a WeChat account is bound on **first start**: the program reads the nickname and WeChat ID of the currently logged-in WeChat and asks “Is this the bot's secondary account?”. Only “Yes” lets it start working and remembers that account; “No” cancels the start (log in to the secondary account in WeChat first). The account card then shows “Bound: nickname (ID)” (“已绑定：…”).
   - **Checked on every later start**: if the logged-in account does not match the bound one, the start is refused (“The logged-in account is …, not the bound bot account — stopped”). **It is also re-checked while running, and the identity is really re-read** (wxauto4's GetMyInfo only returns what was cached at connect time and cannot see an account switch, so each check reconnects to the WeChat window and reads it again): whenever it is about to switch conversations or send and the last check is more than 60 seconds old, the check is done at that moment (the window is being activated anyway, so no extra focus is taken; on a mismatch nothing is read or sent); with no such activity it is checked on its own every 10 minutes; and at once if the main WeChat window has been replaced (logged out and in again). If the account has changed it stops listening and speaking at once and pops up a notification.
   - **What is compared**: the WeChat ID (wxid) first; only if the ID cannot be read, the nickname. When only the nickname is available, any nickname change counts as a mismatch: it stops and asks you to confirm again on the next start.
   - **Switching or fixing the binding**: click “Rebind” (“重新绑定”) on the account card. It clears the remembered identity, restarts the account, and asks again for whatever is logged in at that moment.
   - **Extra safeguard when binding**: if the nickname or WeChat ID that was read matches a person in the People table (the person card's “WeChat ID”, “WeChat secret remark” or WeChat nickname), the confirmation dialog shows a prominent warning “This is the account of ‘×××’ in the People table. Are you sure the bot should speak with it?” (bold red for an admin). **You must confirm a second time to bind**, and the default button is “Cancel”. With no match you confirm once.
   - **The two WeChat fields on a person card have different purposes**: the **WeChat ID** (several allowed) is only this safeguard — it is compared when a WeChat account is bound, so your own account is not mistaken for the bot; the **WeChat secret remark** is what recognises people in WeChat groups (UI automation cannot see the speaker's WeChat ID, only the remark you gave them in the secondary account).
8. **Receive mode** (Settings → Platform settings → WeChat “WeChat receive mode”): **Separate windows** is the original way (each monitored chat is split into its own window); **main-window polling** does not split windows: every few seconds it looks at the session list, switches to a monitored chat that has new messages, reads it, and switches back to the conversation you had open; sending is also done in the main window (switch to that chat, send, switch back). The default is “Auto”: separate windows when the WeChat version is inside wxauto4's supported range, main-window polling when it is outside (for example 4.1.15); if separate windows fail it also switches to polling automatically and writes a log line. The interval is “WeChat new-message check interval” (default 1 second).
   **Before sending anything into a group or a private chat, the program first confirms that the chat now open is exactly the right one; if it does not match, nothing is sent and a log line records it**: it switches by exact name, then reads the conversation title again to check it (and for a private chat also checks that what is open is not a group), and only then sends; when sending it no longer lets WeChat search by name, so a group with a similar name cannot receive the message by mistake. If the check fails, that message counts as not sent (the caller gets a “not sent” error) and the log says who it was meant for and which chat was actually open. Sending a custom sticker (clicking the emoji panel) and looking up the quoted message before a quote reply go through the same switch-and-check first.
   **Not stealing focus**: on WeChat 4.x, wxauto4 brings the WeChat window to the front and takes keyboard focus when it switches to another conversation or reads messages (measured: about 1–2 seconds per read; reading only the session list does not). After each such operation the program **gives the foreground back to the window you were using and puts WeChat back in its previous Z-order** (nothing is done if you were already using WeChat, and it does not fight you if you opened another window meanwhile). To not even see those 1–2 seconds, turn on “Move the WeChat window off-screen” below (reading does not need to bring the window back, so there is no flash). What cannot be avoided: during those 1–2 seconds keyboard focus is still on WeChat — we tested taking focus back while reading and it corrupts the messages that are read, so it is not done; do not type in other windows at that moment, or run the secondary account on another computer.
9. **Move the WeChat window off-screen** (same place, off by default): while the bot runs, the main WeChat window is placed outside all monitors (not minimized — a minimized window cannot be read). It is briefly moved back when switching conversations, sending or checking the identity, then moved out again at once; stopping the bot or quitting the program puts it back. **Three things to know: do not chat manually with the secondary account while it runs; the window will flash when conversations are switched; it still cannot be minimized.** If the identity check fails, the window is not moved and the account does not start. Multiple monitors and high-DPI scaling are handled. If the window is ever left off-screen (for example the program was killed), it is put back automatically at the next start, or you can click “Find the WeChat window” (找回微信窗口) on the WeChat card of the Accounts page. **If the main WeChat window is hidden to the tray (or minimized), the program shows it again by itself — no manual action needed:** when an identity check or a message read cannot reach the interface, it first looks at the main window and, if it is hidden, shows it again (without stealing the foreground) and retries at once; if several tries in a row still fail, the account status is set to an error with the reason and you are notified, so the panel no longer keeps saying “online” while no messages arrive.
10. **After sending a WeChat “custom sticker”**: WeChat closes the emoji panel by itself once a cell is clicked, so the program sees that the panel is already gone and does not press Esc again (that extra Esc used to land on the main WeChat window and make WeChat hide it to the tray). When only browsing or syncing favourites the panel is still open, so Esc is pressed as before.

The program simulates them using web login sessions, so it **may violate the platform's user agreement, and accounts risk being restricted or banned**. Please use a **secondary account**, and first turn on **Settings → Replies → Shadow mode** to run a dry run for a while (she only records “what she would have said” and does not actually send anything).

- On the Accounts page, these platforms are off by default. When adding an account, you must check “I understand the risks” before you can start it.
- All of them work in a “comment area” format: she only replies when someone **@mentions her, replies to her, or sends her a private message**. She does not chime in on her own.
- **Comments, replies, and private messages each have their own pacing and daily limits** (Settings → Platforms). Before each action, the bot waits a random amount of time (15–45 seconds by default). Local deduplication prevents duplicate replies, even after a restart. A message is marked “Replied” only after it is sent successfully. If sending fails, it is retried up to 3 times.
- **When the platform returns a risk-control response, the bot stops immediately** (Bilibili HTTP 412/429, business codes -412/-352/-509/-799; Baidu Tieba captcha or “operating too frequently”; Weibo “requests too frequent”). It sends a Windows notification and does not retry in place. Wait 6–24 hours, log in normally in your browser, and then come back.
- **Bilibili**: Click “Scan to log in” and scan with the Bilibili app on the secondary account. Supports replying to comment @mentions and private messages. Live stream danmaku (bullet comments) are **not implemented**: the official “Live Open Platform” can only receive danmaku from your own live room and has no API for sending danmaku. Unofficial direct connections carry higher risk.
- **Baidu Tieba**: Enter the BDUSS (copy it from Cookies in the browser's F12 developer tools). It reads “@me” mentions and replies to posts. Risk control on replies is very strict (commonly used open-source libraries have removed their reply features because the risk was too high), so keep the frequency very low.
- **Weibo**: Enter the Cookie for m.weibo.cn. It reads “comments that @ me” and replies to them. Replying to private messages is optional.
- The interface details for these three adapters were compiled from public information and have **not been verified on real accounts** (automated tests use simulated services).

## 13. Data, Security, and Migration

- **Key encryption**: Provider API keys, platform tokens, and the panel password are stored in the local database and **encrypted with your Windows account** (DPAPI). If you copy them to another computer or another Windows user, they cannot be decrypted. The panel will show a “Needs to be re-entered” prompt instead of failing silently. You can also keep keys from ever being written to disk by using environment variables (see Section 4).
- **Export (switching computers, keeping a backup)**: Settings → Data & Migration → Export data package. By default, the package **does not include keys** (safer). If you check “Include keys,” the encrypted ciphertext is included, but **it cannot be read after switching computers, so you will need to re-enter the keys**. The data package includes: all settings, roles, personas (including historical versions), the People table, memories, chat history, automatic backups, sticker images, and the backup used by “Undo the last reset” (a snapshot from before the reset, including sticker images).
- **Import**: On the new computer, install the program → open it → in the first step of the setup wizard, set a password → click “Skip wizard” → Settings → Data & Migration → Import, and select that zip file. QQ will need to be scanned again. WeChat requires logging in to the secondary account and downloading the component again.
- **Diagnostics package**: Settings → System → “Package diagnostic info” generates a zip file (version, settings with keys removed, and recent logs; it does not contain keys, chat history, or memories; long numbers in logs are truncated to their last 4 digits). Attach it when reporting an issue. Before sending it, you can extract it and review the contents yourself.
- **New version alerts**: Settings → System: it checks GitHub Releases once a day, and if a new version is available, it shows a notice at the top of the panel. It only notifies you and does not update automatically.
- **English interface**: Settings → System → choose English for “Interface language,” and after refreshing, the entire panel switches to English (the default is Chinese). Content such as chat messages and persona text is not translated. A few background notices and logs remain in Chinese.
- **Installing a new version**: just run the new installer. It stops only PodMates itself (the main program and the panel window) and **does not stop the accounts' NapCat and QQ** (their files live in the data folder, which the installer never writes to); after you reopen the program it re-attaches to the NapCat that was running, and QQ is not logged in again. When the program launches NapCat it does not let it inherit the program's own runtime-library folder (`_internal`), so NapCat and QQ use the runtime libraries in their own folder and in the system and never hold files in the program folder. If a NapCat / QQ process nevertheless has files from the program folder loaded (for example one launched by an older version and never restarted), the upgrade could not overwrite them, so the installer stops it together with the other NapCat / QQ processes of the same account (that account has to log in once more, which beats a half-finished install) and leaves a note in the data folder; the next start writes it to the Logs page (NapCat category, “安装程序：因占用程序目录文件而停掉……”, i.e. “Installer: stopped because it held files in the program folder”).
- **Uninstall**: Start menu → “Uninstall Group Chat Bot Panel.” Uninstalling also stops the NapCat and QQ that PodMates started (they hold files open and the uninstall could not finish otherwise). Neither the install nor the uninstall touches a QQ you opened yourself. It will ask whether you also want to delete your data. The default is “No” (keeping the data so it can be used after reinstalling). Startup-on-boot settings are removed as well.

## 14. Using on a Phone

- **Same Wi-Fi**: Settings → Access & Security → turn on “Allow LAN access” → right-click the tray icon, quit the program, and reopen it → the page will show an address and a QR code. Scan the QR code with your phone to open it, then enter the panel password.
- **Add to Home Screen**: On iPhone, open the page in Safari → Share → “Add to Home Screen.” On Android Chrome → Menu → “Add to Home Screen.”
- **Using it outside**: Use Tailscale (step-by-step instructions are in the panel's “Access & Security” section). **Do not** expose the panel directly to the public internet.

### Using the panel from a phone or another computer (Tailscale recommended)

1. Install Tailscale on the server (or computer) that runs the bot, on your phone, and on any other computer you want to use, and sign in to the **same account** on all of them.
2. In the panel under “Settings → Access & Security”, set the **panel password**, turn on “Allow LAN access”, then right-click the tray icon, quit the program, and open it again.
3. In Tailscale on the server / computer, find this machine's Tailscale address (like 100.x.x.x). On your phone or the other computer, open `http://<the server's Tailscale address>:<port>` in a browser (the port is 18765 by default and can be changed in settings) and enter the panel password.

Once “Allow LAN access” is on, the panel checks the source address of **every request** and accepts only these three kinds; everything else is refused (HTTP 403, with one line in the log): this computer (127.x, ::1); private LAN addresses (10.x, 172.16–31.x, 192.168.x, fc00::/7, fe80::/10); and the addresses used by networking tools such as Tailscale (100.64.0.0/10). So even if the panel runs on a cloud server and listens on all network interfaces, people on the public internet cannot connect.
Only turn on “Also allow public-internet access to the panel” (off by default) if you really need it: it opens the panel to the whole internet over plain http, so the password and chat content may be seen by others, and scanners will try your password. It is risky and not recommended.

## 15. Chat Etiquette, Learning, and Small Tools

Everything in this chapter is optional. Switch things on or off under **Settings → Global defaults** in the “Chime-in”, “Learning” and “Tools” categories. Each can be set per global / platform / role / chat; anything you don't change is inherited from the layer above.

**On by default**

- **Learn the chat's speaking style**: each chat keeps a “style profile” (sentence length, punctuation, common memes and catchphrases, emoji habits; when several chats are bound to the same memory space they share one copy, and clearing it clears it for all of them). It is updated in passing during the memory consolidation call, **at no extra cost**; it is only generated after 30 member messages, and never made up from too little data. She only follows it slightly; persona, identity and attitude, reply language and platform format always take priority. View, edit or clear it under **Memory → Chat style profile** (or on the Chats page). Roles have their own switch; the academic and lifestyle/health templates have it off by default.
- **Remove action descriptions in brackets** (on by default; Settings → Reply, settable at global / role / platform / chat level): models like to write things such as [（尾巴晃了晃）] (the tail swishes) or [（抱着书想了想）] (hugs the book, thinks) in replies. The program tidies this up **before sending**: a line made of just one such bracket is deleted; a single such segment at the start or end of a line is removed. Brackets in the middle of the text and explanatory notes such as [（含税）] (tax included), [（2019 年）] (2019) or [（以上仅供参考）] (for reference only) are never touched. The check is very conservative (anything with digits, Latin letters or a colon is not an action; it must be a clear body part + movement or a gesture phrase): it would rather miss one than delete wrongly. No restriction sentence is needed in the persona.
- **Drop made-up image lines** (on by default; Settings → Reply, next to "remove action descriptions in brackets"; settable at global / role / platform / chat level): other people's pictures appear in the context as "[图片：description]" and her own stickers as "[表情包：description]"; she sometimes copies the format and writes a fake "[图片：…]" in her text as if she had sent a picture, when nothing was sent. **Before sending**, the program deletes every line that consists of nothing but one (or several in a row) of these media markers — "[图片：…]", "[表情包：…]", "[表情]", "[图片]"; markers inside a sentence, or followed by more text, are never touched (it would rather miss one than delete wrongly). If the whole reply ends up empty no text is sent; if she called the sticker tool, the sticker still goes. It is independent of the bracket-action switch.
- **Internal labels do not leak into the text**: if a reply starts with a program-internal label such as [主动插话（……）：] or [【被叫到】], it is removed before sending; the proactive chime-in prompt was also reworded so that it can no longer be copied as a label, and tells her not to write one.
- **After a role switch, the old role's words are no longer taken as her own**: when the same account changes role (schedule, or a “switch to …” command), what the old role said earlier is shown in the context as “<role> (this account's previous role)”; only what the current role said itself is marked as “you” (“she (herself)” for the gatekeeper).
- **Several roles sharing one account do not take each other's self-references as their own**: the account nickname shown in the chat (for example “Dolphin🐬”) is shared by the roles that take turns on duty. Once the account has had more than one role in a chat (or private chat), the system prompt gets an extra section, “【这个号上的几个角色】” (the roles on this account), that only states facts: the nickname is shared by several roles, who is on duty now, who else has spoken on this account before, that wherever the records and memories mention this nickname they mean whichever role was speaking at the time, and that those roles' self-references, catchphrases and past actions are their own; when a “chat speaking habits” profile is shown, a matching sentence is added under it. Nothing is added while only one role has ever spoken on the account. You do not need (and should not) write “you are not …” in a persona. When memories are organised, bot lines are handed to the model as “<role name> (bot role)” instead of the account nickname, and the model is asked to file what each role said or did under that role; the speaking-habits profile no longer takes in bot roles' catchphrases. Memories already stored are left untouched; account nicknames in older recaps are covered by the section above.
- **When the account is muted in a chat it stops trying to speak there**: for QQ this is recognised in three ways — the group-mute notice (a mute or un-mute of this account, whole-group mute on / off), the mute-type error QQ returns when sending (NapCat `result: 120`), and an active query of every group when the account comes online (whole-group mute included; if the account is the owner or an admin, a whole-group mute does not count). When the end time is known it resumes automatically at that time, and immediately on an un-mute notice; when only a send error was seen and the end is unknown, it is re-checked at low frequency (first after 5 minutes, then doubling up to 30 minutes) with a query call — **the re-check never sends anything to the chat**; if the query keeps failing for 48 hours, or the platform cannot be queried at all for 6 hours, it stops treating the account as muted and resumes speaking, with a line in the log (messages are sent as usual again, and a real mute will be recognised again). While muted, the account runs no gatekeeper, writes no replies, does not chime in, start topics, or send scheduled messages / reminders / shift greetings / stickers in that chat, and calls no model for it; it still receives messages, keeps records, consolidates memory and learns stickers, and admin commands still take effect (without a reply). Other accounts in the same chat are unaffected. The state is stored, survives restarts, and expired entries are cleared on start. The Overview and Chats pages show “account X is muted in chat Y until HH:MM” (“end time unknown” when unknown), the Overview's unread notifications get one entry per mute, and manual sending on the Messages page says “Muted — not sent”. Discord (timeout) and Telegram (restricted) use the same mechanism; other platforms do not yet.
- **Resource monitoring**: every hour the program writes one line to the Logs page under the “Resources” category: free physical memory, used virtual memory (commit) as a percentage of its limit, free space on the system drive, whether each account is online, and how many NapCat / QQ / WeChat processes are running. When memory or disk is running low it notifies you the same way as “Message me when something goes wrong” (an unread notification is also left on the Overview, with the current numbers and the processes using the most): used virtual memory ≥ 90% for 5 minutes in a row, or less than 5 GB free on the system drive (the drive holding PodMates' data). Free physical memory is deliberately not used, because Windows uses idle memory as cache so that number is normally low. The same alert is sent at most once a day; if things recover and go wrong again it counts as new. The numbers and the master switch are under Settings → System (advanced), on by default; the checks run inside the program's existing timer loop (memory every minute, disk every hour).
- **Restarts do not lose state**: the chat context (with which role said what), mute and “stop talking” pauses, the hourly / daily chime-in counters and the private-chat history are restored from the database after a restart or upgrade — no need to wait for dozens of new messages. Context cleared by “Reset memory” is not brought back.
- **Model API errors are retried once**: on 429, 5xx or a timeout the request is retried once; if it still fails it is logged and a notice appears on the Overview page. Whether she also says “Disconnected…” in the chat is an option (Settings → Reply → Advanced “Send a line in the chat when the model fails”, off by default; when on, at most once per ten minutes per chat).
- **“Max bots replying to one message” only limits proactive chime-ins**: bots that are @-mentioned, replied to or called by name always reply and take their slots first; the remaining slots go to bots chiming in.
- **Settings has a search box and collapsible categories**: search by name or description at the top of the form (advanced items are found too); on phones the categories start collapsed.
- **Minimum gap between two replies** (default 10 s; Settings → Pacing, settable at global / role / platform / group level, 0 = no limit): after she finishes a reply in a group, she sends no further reply in that group until that many seconds have passed; each group is timed separately. Messages that @ her or reply to her are not lost: they are queued and answered when the time is up (if she is called several times meanwhile they are merged into one reply, and the usual “reply is stale” check runs before it is sent); proactive chime-ins are simply skipped (this and the chime-in cooldown work independently, the stricter one applies); the lines of one split reply are still sent back to back. Private chats are not limited by default; to limit them set “Minimum gap between two replies in private chats” (timed per account × person). The demo mode and comment-style platforms default to 0.
- **Web search**: the main model searches the web via a tool call (the current model must support tool calling; Settings → Models & APIs shows whether it does). By default it uses the **official DeepSeek search API** (`POST /v1/tools/search`, the same key as DeepSeek chat, billed per successful request; DeepSeek states that standalone calls are billed from 2026-11-01). You can switch to Kimi, Zhipu, Tavily, Brave, or your own SearXNG. Search results are used only for that reply and are **never written to memory**; usage is recorded separately as “search”; the daily number of searches is configurable.
- **“Remember…” and reminders**: tell her “remember I don't eat cilantro” and it goes into your personal notes (source marked “Asked to remember by the person”; automatic consolidation never overwrites it, retention-days cleanup skips it, and “forget me” deletes it). Say “remind me in 20 minutes to hand in the homework” or “remind me at 8 tomorrow morning about the meeting”, and when the time comes **whichever role is on duty in that chat** @-mentions you in its own voice. At most 5 pending reminders per person (configurable); they survive restarts; see and delete all of them under **Memory → Reminders**. Works in private chat too, following the private chat scope setting.
- **Filter with code first, then ask the gatekeeper**: for messages that don't @ her, pure emoji, pure links, check-ins, commands starting with `/` or `#`, and messages from other bots are skipped without calling the gatekeeper (saves a call). It only affects proactive chiming in; @-mentions are still always answered. Edit the rules under Settings → Global defaults → Pre-filter rules; in the People table you can mark someone as a bot. The Usage page shows “Gatekeeper calls saved by pre-filter”.
- **Sticker learning**: only “commonly used” stickers are learned: the same image sent by several people or several times (default 2 people or 3 times); near-identical images count as one; the vision model describes it and judges whether it is suitable, and unsuitable content is not learned; at most 10 learned per chat per day, 200 stored per chat, 100 MB total, and the least-used are deleted first when full. The main model decides when to send one, and which one, while replying (tool call: it finds a few candidates for the mood, reads their descriptions and picks one itself, or none), with a configurable frequency; one sticker counts as one message toward the chime-in limits; platforms that can't send images are skipped automatically. See and delete them under **Memory → Stickers**.

**Reply length, timeliness and wording** (Settings → Global defaults → Reply; all adjustable)

- **Per-reply character limit in group chats** (default 300 characters; private chat is unlimited): she is told the limit in the prompt first; if the reply still runs over, the model is asked to compress it to within the limit (at most twice), and only if that fails is it cut at a sentence boundary, **never mid-sentence**; split-sending works on the compressed text.
- **Stale replies**: if new messages arrive in the chat while a reply is being written (by default 3 messages, or any message once writing took more than 20 seconds), the model re-judges the reply with the latest context before sending: send as is, rewrite, or drop it (one extra call, only when stale). Several queued @-mentions of the same bot in one chat are **merged into one reply** that addresses each asker (comment-section platforms reply to each comment separately and are not merged).
- **Who replied to whom, who was @-mentioned**: in the chat history shown to the gatekeeper and the main model, every line carries who the message replies to and who it @-mentions, for example “Alice (reply to Bob): …” and “(@Dolphin) …”, on every platform that provides this information.
- **Wait for the speaker to finish before chiming in** (Settings → Chime-in: “Wait for the speaker to finish before chiming in (seconds)”, default 15, 0 = don't wait; advanced “Maximum wait (seconds)”, default 30; settable at global / role / platform / group level): when someone posts in the group, the gatekeeper is not asked at once; the bot waits until that person has been quiet for this many seconds. If they post again meanwhile the timer restarts; counted from the first message of the run, once the maximum wait is reached she stops waiting and decides about whatever message is newest then. The gatekeeper and she both see the whole run. Where the default comes from: of the next message from the same person, 69% arrive within 15 s; 90% of a run of messages are finished within 29 s. **Only proactive chime-ins wait**: @mentions, replies, being called by name and pokes are handled immediately as before; private chats wait 5 s for the other person to stop by default (see “Wait for the other person to finish in private chats” below). The waiting never blocks other messages in the group. Nothing is asked during the wait and no extra model call is made; the gatekeeper is asked once when the time is up, and cooldown, quota, consecutive-bubble limit, hush, mutes and so on are checked again then. If someone else posts during the wait, this message is no longer chimed in on and is left to the newest one.
- **@ and quotes on WeChat**: WeChat messages carry no structured @, so the program treats an “@name” at the **start** of a message (only whitespace may precede it) as @-mentioning that person, as long as the name exactly matches a member of this group (display names of people who spoke in the recent context, plus the WeChat remarks of those people in the people table). Recognised ones are removed from the text and shown in the chat history like on QQ, as “(@Name) text”, so the gatekeeper and the main model can tell whom the line is addressed to. Names that don't match, names shared by more than one person, and @s in the middle of a sentence stay as plain text; an @ to herself still counts as calling her. For WeChat quote messages, the quoted person's name is split out of the message by wxauto4 (`quote_nickname`) and, if it exactly matches a group member, is recorded as “(reply to Name)”; quoting one of her own lines counts as “replied to you”, as on QQ.
- **Repeated-meme hint**: the program counts memes, terms and metaphors that keep recurring in her last 12 messages in the chat (adjustable) and tells her next time: “already used recently: …, use something else or nothing”; pure statistics, no extra model call.
- **Send short sentences as separate messages** (on by default; applies to chat-type platforms such as QQ, WeChat, Discord and Telegram): **each line of the reply is sent as its own message**, like a person typing one sentence at a time; a line that is very long (over “Split a line by sentence when it is longer than…”, default 160 characters) is split further by sentence. How many she sends in a row is governed by “Max messages in a row when nobody else talks” (default 4): every bubble she sends in a chat (or private chat) counts as one — each line of a split reply, a lone sticker, and the next reply right after; the count restarts from 0 as soon as someone else speaks (being @-ed or replied to counts, so does another of our accounts speaking; “A poke also counts as someone speaking” is on by default). When the remaining count is not enough for a reply, the shortest adjacent lines are merged until it fits; with 0 left, proactive chime-ins and cold-chat openers are not sent. In a private chat the count is kept per “which account × which person” and restarts from 0 when the other person speaks; every reply there answers the other person, so as with an @-mention at least one bubble is always sent even when the count is used up. Panel “let her reply”, reminders, scheduled messages and command receipts are not blocked but their bubbles still count; each of our accounts in the same chat counts separately; 0 = no limit. If a new message arrives while the parts are being sent, the remaining parts are still sent as normal. Comment-section platforms (X, Reddit, YouTube, Bilibili, Tieba, Weibo) and LINE (push messages are quota-limited) do not split by default; you can turn it on in the platform settings.
- **Max replies per hour (per chat, including when @-ed)** (Settings → Rhythm; default 0 = off): each bot account has a reply allowance in each chat that can hold up to “Max allowance to save up” (default 0 = same as the hourly number); each reply uses one, and used ones come back one at a time at the rate of “60 minutes ÷ replies per hour”, also across restarts. Example: 20 per hour, save up to 5 — at most 5 replies in a burst, then one more every 3 minutes, never more than 25 in any 60 minutes. **Counted**: being @-ed / replied to / called by name, pokes, proactive chime-ins, cold-chat openers, and a lone sticker (a reply counts once however many messages it is split into; a sticker following it is not counted again). **Not counted**: panel “let her reply”, reminders, scheduled messages, commands and their receipts, and the line sent when the usage cap is reached. When the allowance is used up, proactive chime-ins and cold-chat openers are simply not sent (the gatekeeper is not even asked); replies to being @-ed / replied to / called by name / poked are not lost but queued until the next allowance returns (several calls in the meantime become one reply; a reply that is stale by then goes through the existing stale check; one waiting while she is told to shut up, is muted or is switched off is dropped). The log says “reply allowance used up, replying in about X minutes (queued)”. “The user calling her does not count toward the limit” (on by default; “the user” = the platform accounts on the fixed “User” card): when he @-s, replies to, calls or pokes her, that reply uses no allowance and is never queued; chime-ins triggered by his messages still count. It stacks with the chime-in limits, cooldown, share cap and “Minimum gap between replies”; the strictest applies.
- **Quoting on chime-ins** (Settings → Reply; on by default): “When chiming in, quote the message she is replying to if others have talked in between” — when the reply is sent and the message she replies to already has at least “Others' messages after the one she replies to” (default 1) messages from others after it, that message is quoted; if it is the newest in the chat it is not. Quoting when @-ed is still governed by “Quote the message when replying to @”. Works on QQ and WeChat: on WeChat the message is found in the chat window by its wxauto4 message id and quoted; if it cannot be found (for example it scrolled out of view) the reply is sent normally and the log notes it.
- **“@name” she writes is sent as a real @** (Settings → Reply; QQ and WeChat; on by default): “@name” in her reply is converted when the name exactly matches a member of the chat (people who spoke in the recent context, plus the QQ nickname / WeChat remark on their People card) and is followed by the end, whitespace or punctuation: QQ replaces that text with a real @ segment (not repeated), a WeChat @ can only sit at the start of a message (wxauto4's `SendMsg(at=…)`), so only an “@name” written at the start of a line (nothing but whitespace before it) is converted and the typed text is removed; one in the middle of a sentence stays plain text. A name shared by several people, our own accounts and names that do not match stay plain text. Nothing is added to the prompt or persona such as “you can @ people”.
- **The QQ account's favourite stickers can be used too** (Settings → Tools; QQ and WeChat; on by default; WeChat is the second item below): the program asks NapCat's `fetch_custom_face` for the stickers the account has favourited in QQ (up to 500 per sync), downloads new pictures and has the vision model write a one-line description for each (duplicates are recognised by image fingerprint, each described once; at most 40 new ones per round, the rest next round), and removes here the ones removed from the favourites. It syncs once at start-up and when the account comes online, then every “Sync favourites every (hours)” (default 24); the **Memory → Stickers** page has a “Sync favourites now” button and marks favourites with a “Favourite” tag. Favourites belong to the account and can be used in every QQ chat it is in (picked together with the stickers learned in that chat); they do not count toward “Max stickers per chat”, and when space runs out only learned ones are deleted; sending one counts like any sticker — towards speech and chime-in limits, the hourly allowance and the messages in a row. By default they are not dropped for “is it a sticker / is it suitable” (they are your own picks); turn on “Also run the content check on favourite stickers” to check them. The favourites in QQ are the source of truth: to remove one, un-favourite it in QQ.
- **Always give her the sticker tool when she is called** (on by default; Settings → Tools; settable at global / role / platform / chat level, same scope as "send stickers"): in a reply to an @, a reply-to-her or her name being called, as long as the platform can send stickers and the account has a usable one, she always gets the `send_sticker` tool, regardless of "chance of giving her the tool". **Having the tool does not mean sending every time**: whether to send is her call. Chime-ins and cold-start topics go by that chance, **100% by default (the tool is given on every reply)**; lower it if she sends too many. With this switch off, being called also goes by the chance. **Stickers work in private chats too**: only from the account's own favourites (QQ favourite stickers, WeChat custom stickers), private chats have no learned stickers; every private reply is a reply to the other person, so it counts as “called” and the switch applies there as well; QQ sends the image to the private chat through NapCat, WeChat opens the sticker panel in that private chat and clicks by fingerprint; a sticker counts as one of the consecutive bubbles in that private chat. When a reply did not get the tool (chance lowered, platform cannot send, model without tool support) while “Send stickers” is on and stickers should have been available, the sentence “This reply cannot send a sticker, text only.” is added at the end of the system prompt, so she does not say she will send one and then send nothing; it is not added when “Send stickers” is off or the account has no stickers at all.
- **Sticker descriptions, candidates and re-describing** (Settings → Tools, advanced, global only): **Maximum length of sticker descriptions** (`sticker_desc_max`, default 250) is the length limit for the description the vision model writes for each sticker; it should cover the picture, any text on it (verbatim), the emotion and the occasions it suits, and it is shown to her when she picks a sticker. Every sticker remembers the length it was described under (old records count as 40). **Re-describe existing ones after the length changes** (on by default): stickers described under a different length are re-described in the background by the vision model (one call per sticker, counted in vision usage, never blocking replies; a missing image file, no vision model, the hard usage cap or a failure on one sticker just skips it until the next round), so after installing this version the existing ones are re-described to 250 automatically; when off, only newly collected stickers are affected. The **Re-describe all stickers** button on **Memory → Stickers** ignores the length and redoes everything. **How many candidate stickers to show her** (`sticker_candidates`, default 10): when she uses the sticker tool the program finds this many of the closest stickers for the mood (ones sent in the last 10 minutes go last; by vector, else by literal match, else the most used ones) and shows their descriptions; she writes a line `【表情+number】` (e.g. `【表情2】`) at the end of her reply to pick one, which is sent after her text; **if none fits she writes nothing and only text goes out**, and a random sticker is no longer sent. All `【表情N】` markers are removed before sending; a marker written without calling the tool is simply removed; with a pick but no text only the sticker is sent. The log line for a sticker carries the mood and which one of how many was picked, and looking at candidates without picking is logged too.
- **Web search while describing stickers** (Settings → Tools, advanced, global only): **Web search when describing stickers** (`sticker_desc_search`, on by default) makes learning a group sticker, describing a newly synced favourite and re-describing look the picture up online first (using the search service chosen in Settings → Models & API); results are only a reference. **Let the vision model decide whether to search** (`sticker_desc_search_auto`, off by default): when off, every sticker is searched at least once — the vision model is first asked for the best search term (text on the picture first), one search is made, then the results are appended to the description prompt and the description is written with the `web_search` tool available; when on, the description is written directly and the vision model searches only if it cannot tell the source or meaning. **Max searches per sticker** (`sticker_desc_search_max`, default 5) caps the searches for one picture. These searches are not limited by “Max searches per day” and do not count toward today's total; usage is recorded under “Sticker search” in Usage → By purpose. With no search service, a vision model without tool support, or a search error, it just looks at the picture. Sticker descriptions are at most 250 characters by default. When writing a description is blocked by the provider's content moderation, it is retried as is **Retries when blocked by content moderation (with search)** (`sticker_block_retry`, default 2) times, then without search, looking at the picture only, **Retries without search after a content-moderation block** (`sticker_block_retry_plain`, default 3) times (if search was not on, it starts there); if every attempt is blocked it stops — a re-description keeps the old text, a newly synced favourite is not taken — both are logged and that sticker is never tried again.
- **Web search when looking at pictures in chats** (Settings → Models, `vis_search`, off by default, same scopes as “Vision”): when on, the vision call for pictures in groups and private chats gets the `web_search` tool and decides itself whether to search, up to “Max search rounds per reply” times; it counts toward “Max searches per day” and slows that reply by a few seconds; the prompt tells it not to search names, accounts or chat content from the picture.
- **Web search that comes with the Coding Plans** (Settings → Models & API → Web search: two new entries, “Z.ai Coding Plan search” and “Zhipu Coding Plan search”, placed after “Zhipu search” in the automatic order): they use the plans' search MCP service (Z.ai: `https://api.z.ai/api/mcp/web_search_prime/mcp`, Zhipu: `https://open.bigmodel.cn/api/mcp/web_search_prime/mcp`) with the plan's own key, and the calls count against the plan's quota. It speaks MCP streamable HTTP (initialize → initialized → tools/list → tools/call, with the session id the server returns; both JSON and event-stream responses are read); the search tool and the query parameter are picked from tools/list rather than hard-coded, and a lost session is re-initialised once.
- **Search keys follow the model key of the same vendor**: every search service can have its own key; when none is entered, the key on the model provider card of the same vendor is used — DeepSeek ← `deepseek`, Kimi ← `moonshotai` / `moonshotai-cn`, Zhipu ← `zhipuai`, Z.ai Coding Plan search ← `zai-coding-plan`, Zhipu Coding Plan search ← `zhipuai-coding-plan`. The panel shows “Using the key of “{card name}”” when following and “Entered (not shown)” when you entered one; removing your own goes back to following.
- **The WeChat account's "Custom stickers" can be used too** (the same three settings in Settings → Tools — "use the account's favourite stickers", "sync favourites every (hours)", "also run the content check on favourite stickers" — now apply to QQ and WeChat; QQ means favourite stickers, WeChat means the "自定义表情" tab of the emoji panel): wxauto4 has no API to send a sticker or to download custom stickers, so the program drives WeChat's emoji panel. **Building the catalog**: in "文件传输助手" (File Transfer), click "发送表情(Alt+E)" in the input bar → switch to "自定义表情" → scroll from the top with the mouse wheel one screen at a time, taking 3 screenshots ~0.3 s apart per screen and computing 3 picture fingerprints per cell (one if all three agree; several distinct ones if the thumbnail animates); the overlap of neighbouring screens gives each cell its index; it stops when no new cell appears. For each new cell the mouse is moved onto it, the enlarged preview is captured and given to the vision model for a one-sentence description (each sticker is described once, at most 40 new per sync), then the mouse is moved away — **only hovering, no cell is ever clicked**. Entries no longer in the panel are removed; if anything goes wrong mid-scan nothing is changed. Timing is as for QQ: at startup / when the account comes online, then every "sync favourites every (hours)"; the "Sync favourites now" button on the stickers page works for WeChat too; building takes the WeChat window for a while (tens of seconds) and other WeChat actions queue behind it. **Sending**: switch to the target group → open the panel → "自定义表情" → scroll straight to the recorded place → take a screenshot and click only if this cell's fingerprint is within tolerance of any fingerprint recorded for the sticker (if not, re-shoot ~0.3 s later, up to 3 shots) → if still no match, search from the top again and update the recorded place; if it is nowhere, nothing is clicked, a log line is written and the text reply goes out as usual → after the click the last few chat messages are read; any new message of her own counts as success, whatever its type or content; WeChat does not list the stickers it sent itself, so this check almost always fails: a normal log line "WeChat: sticker clicked and sent (WeChat does not list its own stickers, so it can't be checked afterwards)" is written, the before/after diagnostics only at debug level, with no retry; the result is used only for logging, and message counts, consecutive-message counts and usage never depend on it → Esc closes the panel and the previous chat is restored. **Click guard**: when sending only "发送表情(Alt+E)", "自定义表情" and the one confirmed cell may be clicked; when building the catalog only the first two; any other control is refused. A WeChat sticker counts like a QQ sticker: speech, chime-in limit, hourly allowance and consecutive-bubble limit. WeChat groups cannot learn stickers yet; only the account's custom stickers are used. WeChat's list is the truth: to remove one, delete it in WeChat.
- **Wait for the other person to finish in private chats, then reply once** (Settings → Pacing: “Wait this many seconds for the other person to stop before replying (private chats)”, default 5, 0 = don't wait; settable at global / role / platform / role-on-platform level, same scope as “Minimum gap between replies in private chats”): when a message arrives she does not reply at once but waits until the person has been quiet for that many seconds — if they send more in the meantime the timer restarts, and counting from the first message of the run she stops waiting after “Wait at most (seconds)” (Chime-in page, 30 by default). When she starts, everything the person sent in this run that she has not answered is treated as what she is replying to (all of it is in the context), and she **answers once**. If the person sends something new while she is writing, the reply is re-checked before sending the same way as “reply is stale” in groups (send as is / rewrite / do not send; it uses the “Re-check the reply if it is stale before sending” switch): send or rewrite counts the new messages as covered and they are not answered separately; do-not-send makes her reply again to the whole run together. “Make her reply to this” in the panel still replies immediately; it is independent of “Minimum gap between replies in private chats”, and the stricter of the two applies. Why 5 s: the next message from the same person arrives within 5 s about a third of the time (59% within 10 s, 69% within 15 s), and writing the reply itself takes ten-odd seconds, so anything added meanwhile is merged in too.
- **WeChat custom-sticker check command**: `PodMates.exe --test-wechat-sticker <output folder>`, run on the machine where PodMates is installed while the **PodMates main program is not running** and WeChat is logged in. Every step goes to `probe.log` and `result.json`; `result.json` holds the fingerprints of all 3 screenshots of every cell (to see which stickers animate and how much), the scrolling method, whether the preview appeared, and the controls clicked. - **WeChat picture check command**: `PodMates.exe --test-wechat-picture <output folder>`, run on the machine where PodMates is installed while the **PodMates main program is not running** and WeChat is logged in. - **Typing speed** defaults to 40 characters/second (it only affects the pause between parts when a reply is split into several messages).

**Other bots**: when another AI is in the chat, tick “This is another bot” on its People card (off by default; it only means “this account is an AI”). How to treat it is layered like any other chime-in setting (global, role, platform, chat); a single role can be set not to skip the gatekeeper, affecting only that role. The choices: “Messages from other bots skip the gatekeeper” (on by default); “When another bot @-mentions or replies to her” has three levels: ignore it / **at most N rounds** (default 1: stop after N consecutive exchanges with the same other bot, and count again once a human speaks in the chat) / reply as usual. This count is separate from the exchange limit between our own bots.

**Optional (the share-of-conversation cap is on by default)**

- **Share-of-conversation cap** (on by default): within “Count the latest messages” (default: the latest 15; it only counts messages and costs no tokens), once all our bots' messages in the chat together reach the limit, they stop chiming in on their own; @-mentions are still answered. The limit can be set two ways, chosen under “Counting method”: **By number** (default) uses “Max messages” (default 7: once they have said 7 of the latest 15 they stop); **By share** uses “Max share (%)” (default 47, roughly 7 out of 15; rounded to a whole percent before comparing). A reply split into several lines counts as one message per line. “Don't block when there are few messages” (off by default, the number is adjustable, default 10): when fewer messages than that are available the cap does not apply; it is mainly for “By share” (with very few messages, one or two bot messages is a huge share), so turning it on is recommended there. When upgrading, anyone who had set a share percentage or counting window is switched to “By share” with “Don't block when there are few messages” on and the same percentage, so the effect is unchanged.
- **Auto-adjust chime-in level**: the gatekeeper also judges whether anyone responded to her last proactive message: it goes up if the conversation continued, and down if she was ignored or found annoying, within the number of steps you allow around the set level (default at most 2 below and 1 above), calculated per bot per chat, and it **recovers over time**, so it never sinks to zero. The Chats page shows the current level and the reasons for recent adjustments. It stacks with account limits, cooldown and the share cap; the strictest wins.
- **Pause chiming in when someone says “stop talking”**: judged by the gatekeeper (same call, no extra cost, no keyword matching). All bots in that chat pause proactive chiming in (default 30 minutes; doubling if told again within an hour, up to 480 minutes); @-mentions are still answered, and an @ to her resumes early. An admin's “be quiet” command is still stronger: full mute.
- **Hard usage cap**: after you set a “daily usage cap”, turn this on; once the day's usage reaches the cap, @-mentions and private chats no longer call the model and only get one fixed sentence (default “今天的额度用完了，明天再来” — “Today's quota is used up, come back tomorrow”; each role can have its own in-character sentence). Memory consolidation, image reading, search, sticker learning and API embeddings are paused too (local embeddings are not affected). It resumes automatically the next day, and the Overview and Usage pages show the current state. The first-run wizard reminds you to set a daily cap (default 0 = unlimited).

## 16. Reset Memory

Panel → **Memory → Memory items** has a "**Reset memory…**" button: use it to make her "forget everything and start over", or to forget only one chat or one person.

- **Scope** (single choice): everything / one memory space / one chat / one person.
- **Content** (multiple choice, all ticked by default): personal notes, chat recaps, group memes (with their vectors), file excerpts, chat style profile, stickers, reminders, and recent chat context (the latest messages the model sees; this covers all chats, including ones not loaded into memory yet; after a reset she no longer remembers "what we were just talking about").
- The confirmation box lists how many items of each kind will be deleted; nothing happens until you confirm.
- **An automatic backup is made first** of the selected content (in the `backups` folder, plus a full database backup in the usual backup scheme); the Memory page then shows "**Undo the last reset**", valid until the next reset, restoring everything (including vectors, sticker images, reminders and chat context).
- **The People table, personas, settings and usage are not part of a reset** and are never touched.

The memory list also has "**Select all current results**", to be used with "Delete selected" and "Approve selected" (the list shows at most 300 items).

## 17. Custom Commands

Panel → **Commands**: define your own “when someone says this, do that”. None by default.

Each command has these parts:

- **Trigger**: whether she must be @-mentioned first (on = @-mentioned, replied to, or called by name; off = triggers whenever anyone in the chat says it, answered by one bot only); match type, one of **Exactly equal** / Contains / Regex.
- **Action**, four kinds: ① **Fixed reply**: sends the text as is, no model call, and you can write `{name}` for the speaker; ② **Let the role answer**: she answers in her own voice with the instruction you wrote, using the normal persona assembly, one model call; ③ **Run a built-in command**: like an alias for a built-in command, e.g. “@her sleep” = be quiet for 480 minutes; ④ **Send a random line**: one of the lines you wrote, no model call.
- **Who can use it**: everyone / only me (admins in the People table) / specific people / a group / group owner and admins. If someone without permission says it, it counts as not triggered and the chat goes on as usual.
- **Where it applies**: platforms, roles on duty and chats can each be restricted (none selected = all).
- **Cooldown**: set per command, the minimum time between two triggers in the same chat; during cooldown it is silently ignored.

In the panel you can add, edit, delete, drag to reorder (earlier ones match first), enable or disable, and **export / import the whole table as JSON**; the edit box has “Try it” to type a line and see which command it would trigger (nothing is executed).

**Permission when aliasing a built-in command**: if the action is “run a built-in command”, “Who can use it” defaults to “Follow the built-in command's permission” (the same as saying the command to her directly: admins only by default). To let everyone use it, change it to “Everyone” yourself; the edit box and the list both warn “open to everyone”.

**Matching order: custom commands → built-in admin commands (be quiet, switch persona…) → normal chat.** A custom command can override a built-in one of the same wording. **No script or code execution is offered.** Custom commands obey shadow mode (record only) and quiet hours; while the hard usage cap is in effect only “Let the role answer” is not executed, the other three still run.
